# Contributing

Thanks for your interest in contributing. This project is maintained by Prakash Maheshwaran.

## Reporting issues

Use the GitHub issue tracker. Pick the right template:

- **Bug report** — for anything broken
- **Feature request** — for new ideas or scope changes
- For questions, open a regular issue with a clear title

Before opening a new issue, search existing ones. Duplicate issues slow things down.

## Pull requests

1. Fork the repo and create a branch off `main`.
2. Make your change. Keep the diff focused. One concern per PR.
3. Run the project's tests locally before pushing.
4. Use the PR template. Fill in the summary and the test plan.
5. Open the PR against `main`.

PRs that don't pass CI won't be reviewed. PRs that touch unrelated files or try to bundle multiple changes will be asked to be split.

## Labels we use

| Label | Meaning |
|---|---|
| `bug` | Confirmed broken behavior |
| `feature` | New functionality request |
| `docs` | Documentation only |
| `question` | User is asking, not filing |
| `good first issue` | Beginner-friendly, mentoring welcome |
| `help wanted` | Maintainer is open to outside help |

## Voice

Read a few existing issues and PR comments before writing your first comment. Match the tone of the repo, don't impose a different one.
